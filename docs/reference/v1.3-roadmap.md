# v1.3 Roadmap: Browser, Email, and Office Infrastructure Deployment

## Executive Summary

## Phase 1: Browser (Jetski Sidecar Deployment)

### What's Already Built
- **Jetski Dockerfile**: Multi-stage Alpine build with Lightpanda engine + Go Observer
- **CDP Proxy**: Full CDP WebSocket proxy with PII scrubbing at net.Conn level
- **SQLCipher Sessions**: PBKDF2-HMAC-SHA512, 256k iterations
- **Matrix HITL**: Approval flow for sensitive browser operations (60s timeout)
- **NavChart Pipeline**: 6-stage CDP frame → NavChart normalization
- **Observer**: Go CDP buffer with 5s watchdog, semantic locators, anti-WAF

### What's Needed
1. **VPS Deployment**: Deploy Jetski as Docker sidecar alongside bridge
   - Add `jetski` service to `docker-compose.yml`
   - Configure bridge → Jetski CDP connection (`ws://jetski:9222`)
   - RPC connection (`http://jetski:9223`)
2. **Browser Handler Wiring**: Register Jetski RPC in bridge config
   - `cfg.Browser.Backend = "jetski"`
   - `cfg.Browser.CDPUrl = "ws://jetski:9222"`
   - `cfg.Browser.RPCUrl = "http://jetski:9223"`
3. **Chrome/Chromium Fallback**: Optional full browser for JavaScript-heavy sites
   - Puppeteer/Playwright container as fallback
   - Configuration toggle in `config.toml`

### Resource Estimates
| Resource | Jetski Only | + Chrome Fallback |
|----------|-------------|-------------------|
| RAM | +128 MB | +512 MB |
| Disk | +50 MB | +500 MB |
| CPU | Minimal | Moderate |

### Dependencies
- None (can deploy independently)

### Estimated Effort: 1-2 days

## Phase 2: Email Pipeline (Postfix Infrastructure)

### What's Already Built
- **EmailDispatcher**: Full dispatch engine with template-based routing
- **Team Routing**: TeamMatcher + TeamAgentLookup + TeamRoutedEmailEvent
- **RoutingRuleStore**: SQLite-backed persistent routing rules with pattern matching
- **HITL Approval**: Email approval/rejection flow via Matrix
- **IMAP Ingest**: Email ingestion from IMAP servers
- **SMTP Client**: Outbound email via SMTP
- **Gmail/Outlook Clients**: Platform-specific email adapters
- **Template Engine**: EmailTemplate system with variable substitution
- **Thread Tracker**: Conversation threading

### What's Needed
1. **Postfix MTA**: Deploy Postfix as local mail transfer agent
   - Docker container with Postfix + Dovecot
   - Domain configuration (MX records)
   - TLS certificates (Let's Encrypt / Cloudflare)
2. **Email RPC Registration**: Wire email methods into bridge RPC server
   - `email.send`, `email.list`, `email.get`
   - `email.set_team_routing`, `email.get_team_routing`
3. **Queue Management**: Persistent email queue for retry/reliability
   - SQLite-backed queue with retry logic
   - Rate limiting per domain
4. **DNS Configuration**: MX, SPF, DKIM, DMARC records

### Resource Estimates
| Resource | Postfix Stack |
|----------|---------------|
| RAM | +256 MB |
| Disk | +100 MB |
| CPU | Minimal |

### Dependencies
- Requires domain with DNS access
- Requires TLS certificates

### Estimated Effort: 3-5 days

## Phase 3: Office Document Pipeline

### What's Already Built
- **Python Sidecar (MarkItDown)**: XLSX, PPTX, MSG, XLS, DOC, PPT support
  - Dockerfile: python:3.12-slim + grpcio + markitdown + olefile + xlrd
  - 61 tests: worker, edge cases, interceptor, Docker integration
  - HMAC-SHA256 token validation
  - TTL recycling (50 requests → container restart)
- **Go Bridge Routing**: 3-layer document pipeline
  - Layer 0: Plain text bypass (native Go)
  - Layer 1: Valid magic + MIME → Python or Rust sidecar
  - Layer 2: Strict drop on magic mismatch
- **YARA CDR**: Content disarm and reconstruction in bridge
- **Split-Storage RAG**: Document chunking with separate embedding storage

### What's Needed
1. **Deploy Python Sidecar**: Add to Docker Compose
   - `sidecar-office` service with gRPC socket mount
   - Network isolation (`NetworkMode: none`)
   - Security hardening (`cap_drop: ALL`, `ReadonlyRootfs: true`)
2. **Rust Sidecar Completion**: PDF text extraction, DOCX editing
   - Currently 40% built (S3 storage, circuit breaker done)
   - Need: PDF extraction, DOCX read/write, merge/split
3. **Sidecar Orchestration**: Wire into bridge via skill router
   - `document_processing` skill → Python sidecar image
   - `pdf_processing` skill → Rust sidecar image
   - Use `SkillRouter` from v1.2 T4

### Resource Estimates

### Dependencies

### Estimated Effort: 2-3 days (Python), 5-7 days (Rust)

## Phase 4: Risk Threshold Configuration

### What's Already Built
- `RiskClassifierImpl`: Hardcoded risk taxonomy with map-based classification
- `CategoryConfig`: Thread-safe config with permission levels and audit
- `ConfigStore` (v1.2 T6): SQLite persistence for dynamic PII config

### What's Needed
1. **Restructure Risk Classifier**: Replace hardcoded map with configurable taxonomy
   - Database-backed risk rules
   - Runtime update via RPC (`security.set_risk_threshold`)
   - Custom category support
2. **Risk Scoring Engine**: Weighted scoring across multiple risk factors
3. **Escalation Policies**: Automatic escalation based on risk score thresholds

### Estimated Effort: 5-7 days

### Recommendation
- **2 GB VPS**: Can run all v1.3 services but tight on RAM
- **4 GB VPS**: Recommended for production with headroom

If RAM is constrained, deploy in priority order:
1. Jetski (128 MB) — highest value, lowest resource
2. Python Sidecar (256 MB) — document processing
3. Postfix (256 MB) — email infrastructure
4. Rust Sidecar (128 MB) — heavy document processing
