### Must NOT Have (Guardrails)
- NO Voice implementation changes (`bridge/pkg/voice`, `pkg/webrtc`, `pkg/turn`) — transport-only test migration allowed
- NO ArmorChat Android code — bridge + API contracts only
- NO removal of SQLCipher, Matrix control plane, or approval flow
- NO weakening of approval flow for payments or critical PII
- NO direct production secret access
- NO rewrites of existing working code — minimal patches only
- NO changes to `container-setup.sh` or `deploy/container-setup.sh`
- NO changes to `bridge/pkg/yara/scanner.go` internal logic
- NO changes to `cmd/` directory
- NO structured logging library (stdlib `log` only)
- NO ad-hoc RPC registration pattern — any v1.2 RPC additions must:
  - Live under existing Bridge RPC registration flow
  - Be documented in `docs/reference/api-contracts-v1.2.md`
  - Include request/response contract tests
  - Preserve existing 109-method behavior unless explicitly versioned
  - Return fail-closed errors on missing auth, sealed keystore, or policy denial
- NO bare `file.*` RPC methods — use `secretary.artifact_*` namespace

### v1.2.1 / v1.3 Deferred Features
These are valid features but are NOT part of v1.2 stabilization:
- Approval delegation
- Dynamic PII class configuration
- Email team-based routing
- Email reply threading
- Dynamic skill-based sidecar spawning
- User-configurable risk thresholds
- Cross-workflow state management

### Security Rules (Fail-Closed)
- **Artifact protocol**: Reject artifacts without owner/workflow binding
- **Artifact download**: Require workflow/user authorization check
- **File metadata**: Sanitize MIME type, filename, tags, source, destination
- **Checksums**: SHA-256 is integrity only; do not present as authentication
- **SQLite store**: Enforce TTL cleanup and maximum artifact size
- **Email audit**: Do not expose raw sender/recipient PII in audit output
- **Dynamic sidecars**: Require allowlisted images only; no workflow-supplied image names
