=== 4. Unquoted variable expansions in bash commands ===

File: .skills/provision.yaml
  Line 42: sudo $CMD
    Context: $CMD is unquoted — word splitting and globbing risks
    Severity: MEDIUM — if expiry param contains spaces/special chars, could cause unexpected behavior
  Line 248: CF_API_TOKEN="$CF_API_TOKEN" $SETUP_CMD (cloudflare.yaml)
    Context: $SETUP_CMD is unquoted when executed
    Severity: MEDIUM — domain/mode values with spaces could cause word-splitting issues

File: .skills/status.yaml
  Line 91: $SSH_CMD "docker info >/dev/null 2>&1 && echo '✓ Docker daemon running' || echo '✗ Docker daemon not running'"
    Context: $SSH_CMD used as bare variable (word-split intentional for command execution)
    Severity: LOW — intentional pattern for SSH command execution, but fragile

=== 5. return 0 used outside functions (bash error) ===

File: .skills/status.yaml
  Line 150: return 0
    Context: check_ssl step — uses `return 0` to exit early when no domain provided
    Severity: HIGH — `return 0` only works inside a function. These step commands run as
    inline scripts, not functions. This will produce "return: can only `return' from a
    function or sourced script" error. Should be `exit 0` instead.
