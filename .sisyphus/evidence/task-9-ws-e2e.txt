## Architecture Notes

The test uses a mock EventBroadcaster (implements websocket.EventBroadcaster interface)
instead of importing the real HTTP server, because the HTTP server transitively depends
on the YARA C library (via rpc → yara), which is not available in the build environment.

The E2E test creates:
1. A real httptest.Server with gorilla/websocket handler
2. A mock EventBroadcaster wired as the WebSocket adapter's broadcaster
3. A real gorilla/websocket client connecting to the test server
4. The EventBus wired to publish through the adapter

The flow tested: EventBus.PublishBridgeEvent → ws.Server.Broadcast → mockBroadcaster.BroadcastEvent → wsHandler.broadcast → gorilla/websocket client

## Known Issue (Production Code — Not Modified)

BaseEvent.ToJSON() uses `json.Marshal(e)` where `e` is `*BaseEvent`, causing method
promotion to only serialize BaseEvent fields (type, timestamp) instead of the full
concrete event struct. The EventWrapper.Data field therefore contains only type+timestamp
for the inner event. This is a Go method-receiver gotcha, not a test issue.

## Note on Test Location

Tests placed in `bridge/pkg/eventbus/` (not `bridge/pkg/http/`) due to build dependency:
- `bridge/pkg/http/server.go` imports `bridge/pkg/rpc` which transitively imports `github.com/hillu/go-yara/v4`
- YARA C library headers not available in build environment
- `bridge/pkg/eventbus/` builds cleanly without YARA
