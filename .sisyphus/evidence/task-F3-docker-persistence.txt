### 1. Code Review: Container Detection & Key Persistence

**File:** `bridge/pkg/keystore/keystore.go`

#### deriveMasterKey() Implementation (Lines 193-233)

The 4-tier priority system is correctly implemented:

```go
// Priority 1: Environment variable
if secret := os.Getenv("ARMORCLAW_KEYSTORE_SECRET"); secret != "" {
    return decoded[:32], nil
}

// Priority 2: Explicit secret file
keyPath := ks.dbPath + ".key"
if data, err := os.ReadFile(keyPath); err == nil {
    if key, err := base64.StdEncoding.DecodeString(string(data)); err == nil {
        return key, nil
    }
}

// Priority 3: Container-persisted key
if ks.isContainerized() {
    key := make([]byte, 32)
    if _, err := io.ReadFull(cryptorand.Reader, key); err != nil {
        return nil, fmt.Errorf("failed to generate container key: %w", err)
    }
    encoded := base64.StdEncoding.EncodeToString(key)
    if err := os.WriteFile(keyPath, []byte(encoded), 0600); err != nil {
        return nil, fmt.Errorf("failed to persist key: %w", err)
    }
    return key, nil
}

// Priority 4: Hardware-derived key
return ks.deriveHardwareKey()
```

**Critical Finding:** When running in a container (Priority 3), the code:
1. Generates a random 32-byte key
2. Persists it to `keystore.key` file
3. Returns the key for use

This ensures the key survives container restarts because:
- The key is persisted to disk (not memory-only)
- On subsequent restarts, Priority 2 reads the persisted key
- Container detection ensures this path is only taken in containers

#### isContainerized() Implementation (Lines 235-289)

## Persistence Logic Flow

### First Container Start (No existing key)

1. `deriveMasterKey()` called
2. Priority 1: No `ARMORCLAW_KEYSTORE_SECRET` → Skip
3. Priority 2: No `keystore.key` → Skip
4. Priority 3: `isContainerized()` returns true
5. Generate random 32-byte key
6. Write key to `keystore.key` (base64-encoded)
7. Return key to caller
8. Database encrypted with this key

### Container Restart

1. `deriveMasterKey()` called
2. Priority 1: No `ARMORCLAW_KEYSTORE_SECRET` → Skip
3. Priority 2: **Found `keystore.key` file**
4. Read and decode key from file
5. Return key to caller
6. Database decrypted with same key ✓

### Container Recreation (simulate Docker upgrade)

1. Old container stopped and removed
2. New container created with same volume mounts
3. `deriveMasterKey()` called
4. Priority 2: **Found `keystore.key` file** (persisted in volume)
5. Read and decode key from file
6. Return key to caller
7. Database decrypted with same key ✓
